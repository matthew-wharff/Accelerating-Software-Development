## Root Causes Grouped

### A. Tests that make real network calls but aren't marked `integration` (2 tests)

- `tests/test_claude_api.py::test_claude_api`
- `tests/test_e2b_sandbox.py::test_e2b_sandbox`

These would pass with real API keys and unblocked egress, but in the sandboxed CI/dev environment they fail. The fix is to mark them `@pytest.mark.integration` so `pytest -m "not integration"` skips them.

### B. Wrong mock target in `tests/test_e2b_node.py` (5 tests)

All five `test_e2b_node_*` failures share the same bug: the tests patch `e2b_code_interpreter.Sandbox` so that *calling* the class returns `mock_sandbox`, but the production code at `graph/pipeline.py:696` calls `Sandbox.create(...)`. The classmethod call bypasses the `return_value` and produces an auto-generated `MagicMock`. The fix is either:

- patch `Sandbox.create` directly (e.g. `patch("e2b_code_interpreter.Sandbox.create", return_value=mock_sandbox)`), or
- set the patched class's `.create.return_value = mock_sandbox`.
